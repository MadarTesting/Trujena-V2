Use case ID
UC- 6
Name
إدارة طلبات إنشاء التطبيقات 
Description
يستطيع الادمن عرض وإدارة جميع طلبات إنشاء التطبيقات المرسلة من التجار، ومراجعة بيانات الطلب، وتحديث حالته خلال مراحل التنفيذ المختلفة، وإدخال بيانات التهيئة ، ورفع ملفات التطبيق، وإدارة عملية النشر حتى إتاحة التطبيق على المتاجر ،بالإضافة إلى إمكانية الدخول إلى لوحة تحكم التاجر باستخدام Admin Mode والتحكم في إمكانية تعديل إعدادات التصميم أثناء مراحل نشر التطبيق. 
Actor
السوبر ادمن 
ادمن لديه صلاحية إدارة طلبات انشاء التطبيق .
ادمن لديه صلاحية Access Merchant Dashboard / Login as Merchant عند الحاجة إلى الدخول إلى لوحة تحكم التاجر. 
Pre-Conditions
الادمن مسجل دخول إلى النظام
لديه صلاحية إدارة طلبات انشاء التطبيقات
يوجد طلبات إنشاء تطبيقات مرسلة من التجار 
حساب التاجر المرتبط بالطلب موجود وفعال. 
في حالة استخدام Admin Mode، يجب أن يمتلك الأدمن الصلاحية الخاصة بالدخول إلى لوحة تحكم التاجر.

يقوم الادمن بإدخال بيانات البريد الإلكتروني وكلمة المرور  والضغط على زر Create ليقوم النظام بإنشاء البريد الإلكتروني للتاجر تلقائيا على Mail Server المرتبط بالـ Webmail. 
بعد نجاح إنشاء البريد الإلكتروني، يقوم الادمن بإدخال باقي بيانات التهيئة وحفظها. 
بعد نجاح حفظ بيانات التهيئة تتحول الحالة تلقائيا من "جاري الاعداد" الي "قيد التنفيذ".
يبدأ الادمن تنفيذ التطبيق وتجهيز  ملفات التطبيق .
يقوم الأدمن برفع ملف التطبيق APK / AAB. 
بعد نجاح رفع الملف تتحول حالة الطلب تلقائيا إلى "جاهز للمراجعة" ليقوم العميل بمراجعته.
عند مراجعة العميل للتطبيق في حالة الموافقة يتم تحويل الحالة تلقائيا الي في "انتظار النشر" وفي حالة طلب تعديل من العميل يتم تحويل الحالة إلى "طلب تعديل".
بعد موافقة العميل، يقوم الأدمن بتحويل الطلب إلى "قيد النشر" والبدء في إجراءات نشر التطبيق على المتاجر. 
في حالة طلب تعديل يقوم الادمن بمراجعة ملاحظات العميل ويقوم الادمن بتحويل الحالة إلى "قيد التنفيذ" ويتم تنفيذ التعديلات ثم اعادة رفع نسخة جديدة من التطبيق (APK / AAB) ف تتحول الحالة تلقائيا مرة أخرى إلى “جاهز للمراجعة”.
نشر التطبيق على المتاجر 
عند نجاح نشر التطبيق على أول متجر يقوم الأدمن بإدخال رابط المتجر المنشور وحفظ الرابط داخل الطلب .
يتم اشعار التاجر عند حفظ الرابط .
تظل حالة الطلب "قيد النشر" لأن عملية النشر لم تكتمل على جميع المتاجر المطلوبة. 
تصبح لوحة تحكم التاجر مفتوحة ويتمكن التاجر من الدخول إليها والتحكم في إعدادات التصميم المسموح بها. 
يمكن للتاجر بعد فتح لوحة التحكم تعديل إعدادات التصميم وفقا للصلاحيات المتاحة له. 
عند بدء الأدمن إجراءات نشر التطبيق على المتجر الثاني، يستطيع الأدمن تفعيل خيار "قفل لوحة التاجر ". 
عند تفعيل القفل : 
يتم منع التاجر من تعديل إعدادات التصميم داخل لوحة التحكم. 
تظهر له رسالة توضح أن لوحة التحكم مقفلة مؤقتا بسبب وجود عملية نشر قيد التنفيذ.
تظل حالة الطلب "قيد النشر".
يستطيع الأدمن الدخول إلى لوحة تحكم التاجر باستخدام Admin Mode وفقا لصلاحياته، حتى أثناء قفل لوحة التاجر. 
بعد نجاح نشر التطبيق على المتجر الثاني، يقوم الأدمن بإدخال رابط المتجر الثاني. 
يتحقق النظام من وجود روابط المتاجر المطلوبة:
Google Play.
App Store.
بعد إدخال الرابطين الصحيحين وحفظهما تتحول حالة الطلب تلقائيا الي "تم النشر" .
يتم إلغاء قفل لوحة تحكم التاجر تلقائيا. 
يستطيع التاجر الدخول إلى لوحة التحكم والتحكم في إعدادات التصميم مرة أخرى.
يتم إرسال إشعار للعميل بتحديث حالة الطلب.
يتم تسجيل جميع تغييرات الحالة وعمليات قفل والدخول الي لوحة التاجر داخل Activity Log. 
الدخول الى لوحة تحكم التاجر باستخدام Admin Mode 
يظهر للأدمن الذي يمتلك صلاحية Access Merchant Dashboard خيار "الدخول الى لوحة التاجر". 
عند الضغط عليه، يقوم النظام بفتح لوحة تحكم التاجر باستخدام Admin Mode / Impersonation 
لا يحتاج الأدمن إلى إدخال اسم مستخدم أو كلمة مرور التاجر 
يتم فتح لوحة التاجر في تبويب جديد مع استمرار جلسة الأدمن في لوحة الإدارة. 
يظهر النظام شريط تنبيه أعلى لوحة تحكم التاجر يوضح أن الأدمن يستخدم لوحة التاجر في وضع Admin Mode، مع توضيح أن بعض الإعدادات والوظائف تكون مقيدة أثناء هذا الوضع. 
يعرض النظام للأدمن داخل لوحة التاجر الوظائف المسموح له بالوصول إليها وفقا لصلاحيات Admin Mode، وتشمل إعدادات التصميم، الإعلانات والإضافات وإدارة عناصر التطبيق، مع إمكانية عرض متابعة طلب الإنشاء وتفاصيل الطلب دون تعديلها.
يتمكن الأدمن من تنفيذ الإجراءات المسموح بها داخل لوحة التاجر وفقًا لصلاحيات Admin Mode 
يتم تنفيذ الإجراءات على بيانات التاجر الفعلية. 
يتم تسجيل الدخول إلى لوحة التاجر داخل سجل النشاطات متضمن ( اسم الادمن ، اسم التاجر ، نوع العملية ، تاريخ ووقت الدخول )
عند الانتهاء، يستطيع الأدمن العودة إلى لوحة الإدارة دون الحاجة إلى تسجيل الدخول مرة أخرى. 
Post Condition
يتم حفظ بيانات التهيئة داخل Profile التاجر.
يتم رفع ملفات التطبيق وربطها بالطلب.
يتم حفظ روابط Google Play وApp Store داخل الطلب.
تظل حالة الطلب "قيد النشر" حتى يتم إدخال روابط المتاجر المطلوبة.
تتحول حالة الطلب إلى "تم النشر" بعد إدخال الرابطين الصحيحين.
يتم فتح لوحة تحكم التاجر بعد نشر أول متجر.
يمكن للأدمن قفل لوحة تحكم التاجر أثناء نشر المتجر الثاني.
يتم فتح لوحة تحكم التاجر تلقائيا بعد اكتمال النشر على المتجرين.
يتم إرسال إشعارات للعميل عند تحديث حالة الطلب.
يتم تسجيل جميع العمليات داخل سجل التحديثات وActivity Log.
يتم تسجيل جميع العمليات التي تمت باستخدام Admin Mode مع تحديد الأدمن الذي نفذها.

Business Rules
لا تتغيير الحالة إلا بالتسلسل المنطقي المحدد .
لا يمكن بدء التنفيذ قبل إدخال وحفظ بيانات التهيئة المطلوبة. 
بيانات التهيئة تحفظ داخل Profile التاجر في لوحة تحكم الادمن .
تعرض كلمات المرور مشفرة .
عند رفع APK / AAB تتغير حالة  الطلب تلقائيا إلى "جاهز للمراجعة ".
لا يمكن تحويل الطلب إلى قيد النشر بدون موافقة العميل.
عند نشر التطبيق على متجر واحد فقط وإدخال رابطه، تظل حالة الطلب "قيد النشر".
لا تتحول حالة الطلب إلى "تم النشر" إلا بعد إدخال روابط المتاجر المطلوبة بشكل صحيح.
يجب إدخال رابط Google Play ورابط App Store لإتمام حالة "تم النشر".
يمكن نشر التطبيق على أحد المتاجر أولا دون انتظار المتجر الآخر.
بعد إدخال رابط أول متجر، يتم فتح لوحة تحكم التاجر ويستطيع التاجر تعديل إعدادات التصميم.
عند بدء عملية النشر على المتجر الثاني، يستطيع الأدمن تفعيل قفل لوحة التاجر لمنع التاجر من إجراء تعديلات أثناء النشر.
عند تفعيل قفل لوحة التاجر، لا يستطيع التاجر تعديل إعدادات التطبيق حتى انتهاء عملية النشر.
كل عملية قفل أو فتح للوحة تحكم التاجر يتم تسجيلها في Activity Log.
لا يؤثر قفل لوحة التاجر على صلاحية الأدمن في الدخول باستخدام Admin Mode وفقا لصلاحياته.
بعد إدخال روابط المتاجر المطلوبة وتحول الحالة إلى "تم النشر" يتم إلغاء قفل لوحة التاجر تلقائيا.
لا يمكن التحكم في الغاء او تفعيل قفل لوحة التحكم الا بعد رفع احدي روابط التطبيق على المتاجر.
لا يمكن تجاوز أي حالة بدون استيفاء شروطها.
لا يمكن حفظ بيانات التهيئة قبل نجاح إنشاء البريد الإلكتروني.
لكل تاجر بيانات مستقلة خاصة به (Email / OneSignal / Firebase).
يتم الاحتفاظ بأحدث نسخة من ملفات التطبيق باعتبارها النسخة النشطة
لا يظهر خيار الدخول الي لوحة التاجر إلا للأدمن الذي يمتلك صلاحية Access Merchant Dashboard. 
لا يحتاج الأدمن إلى معرفة أو إدخال كلمة مرور التاجر لاستخدام Admin Mode. 
يتم فتح لوحة تحكم التاجر في نافذة أو تبويب جديد مع الحفاظ على جلسة الأدمن الحالية.
جميع العمليات التي ينفذها الأدمن داخل لوحة تحكم التاجر تنفذ على حساب التاجر الفعلي.
لا يسمح بتعديل بيانات حساب التاجر الأساسية. 
يقتصر استخدام Admin Mode على إدارة وتشغيل المتجر : 
متابعة الطلبات وتفاصيلها ( للعرض فقط )
 إعدادات التصميم
الاضافات والإعلانات 
إدارة عناصر التطبيق 
لا يسمح بتعديل بيانات حساب التاجر الأساسية. 
يتم تسجيل عملية الدخول إلى لوحة تحكم التاجر باستخدام Admin Mode داخل Activity Log مع اسم الأدمن واسم التاجر وتاريخ ووقت الدخول.
يتم تسجيل جميع الإجراءات التي ينفذها الأدمن داخل Admin Mode باسم الأدمن وليس باعتبارها إجراءً صادرًا من التاجر.
عند انتهاء Admin Mode تستمر جلسة الأدمن في لوحة الإدارة.
في حالة كون لوحة تحكم التاجر مقفلة، يتم تطبيق حالة القفل على الأدمن أيضا بالنسبة للوظائف التي تم منع التاجر من تعديلها، ولا يمكن للأدمن تنفيذ التعديلات إلا إذا كانت صلاحية Admin Mode الخاصة به تسمح بتجاوز القفل.

تغيير حالة الطلب.

إضافة أو تعديل روابط المتاجر.
قفل لوحة التاجر.
الدخول الي لوحة التاجر.
الدخول باستخدام Admin Mode.
الإجراءات التي تمت من خلال Admin Mode.
رفض الطلب وسبب الرفض.
طلب تعديل العميل.
أي إجراءات إدارية أخرى مرتبطة بالطلب.
